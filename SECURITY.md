# Security policy

## Supported versions

Security fixes are made on the current `main` branch. Tagged pre-1.0 releases are snapshots and are not maintained as separate support lines.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting feature for the repository. If that feature is not yet available, contact the repository owner privately through the contact method on their GitHub profile.

Please include:

- the affected commit or release;
- steps to reproduce;
- the impact you believe is possible;
- any proof-of-concept code in the smallest safe form; and
- whether the issue has been disclosed elsewhere.

Do not open a public issue for an unpatched vulnerability and do not access data or systems you do not own. The project is a client-side simulation with browser-local saves; reports concerning deployment infrastructure should identify the relevant deployment separately from the open-source application.

You should receive an acknowledgement within seven days when the repository is actively maintained. A fix timeline will depend on severity, reproducibility, and maintainer availability.
